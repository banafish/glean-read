## 新增需求

### 需求:微信文章 URL 必须可回写到快照
当获焦的快摘弹窗从剪贴板识别出微信公众号文章链接时，系统必须把该链接回写到最近页面上下文缓存，供同一文章的后续摘录复用。

#### 场景:回写保留已有标题
- **当** 快摘弹窗读到 `mp.weixin.qq.com` 链接且缓存中已有微信快照
- **那么** 系统必须只覆盖快照的 URL 字段并刷新采集时间，禁止清空已识别的标题

#### 场景:无微信快照时新建
- **当** 快摘弹窗读到 `mp.weixin.qq.com` 链接但缓存中没有微信快照
- **那么** 系统必须新建一条仅含 URL 的微信快照

### 需求:复制信号必须被记录用于剪贴板新鲜度校验
无障碍服务必须记录微信复制类点击的时间戳（不含剪贴板内容本身），供快摘弹窗判定剪贴板内容是否来自本次复制。

#### 场景:剪贴板时间戳可用
- **当** 快摘弹窗读取剪贴板且系统提供了剪贴板时间戳
- **那么** 系统必须要求剪贴板时间戳与最近复制信号的偏差在容差内，否则视为陈旧内容拒绝使用

#### 场景:剪贴板时间戳不可用
- **当** 设备 ROM 未提供剪贴板时间戳
- **那么** 系统必须退化为"距最近复制信号不超过兜底时间窗"的校验

## 修改需求

### 需求:最近页面上下文缓存必须受有效期约束
系统必须对最近页面上下文缓存应用严格有效期，禁止把过期快照用于新的快摘补齐；有效期必须按来源宿主区分：浏览器快照 60 秒，微信公众号快照 10 分钟。

#### 场景:读取未过期快照
- **当** 消费方读取最近页面上下文缓存，且当前时间仍处于该快照来源宿主对应的有效期内
- **那么** 系统必须返回该快照用于后续来源补齐

#### 场景:读取过期快照
- **当** 消费方读取最近页面上下文缓存，且快照已超过其来源宿主对应的有效期
- **那么** 系统必须把该快照视为不可用，并禁止用其补齐新的摘录来源

#### 场景:微信快照使用延长有效期
- **当** 缓存中的快照来源为微信公众号（`com.tencent.mm`）
- **那么** 系统必须以 10 分钟为有效期判定，以覆盖"复制链接后继续阅读再复制正文"的使用节奏
