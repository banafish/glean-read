## 新增需求

### 需求:公众号文章页复制动作必须触发摘录气泡
当用户已开启辅助识别且微信摘录气泡开关打开时，系统必须在微信公众号文章页识别「复制成功」toast（自绘菜单按钮点击事件不携带文本，无法按钮级识别），并弹出摘录悬浮气泡。

#### 场景:文章页复制正文
- **当** 用户在微信公众号文章页长按选中文本、点击微信自带「复制」并出现复制成功 toast
- **那么** 系统必须在屏幕边缘弹出摘录气泡，并记录复制成功信号时间戳

#### 场景:文章页复制链接
- **当** 用户在微信公众号文章页通过「⋯」菜单点击「复制链接」并出现复制成功 toast
- **那么** 系统必须弹出同一个摘录气泡，并记录复制成功信号时间戳

#### 场景:非文章页复制不触发
- **当** 用户在微信聊天等原生页面复制文本（当前窗口无网页容器节点，且最近的微信窗口类名不含 WebView）
- **那么** 系统禁止弹出摘录气泡

#### 场景:多语言 toast 识别
- **当** 微信界面语言为简体中文、繁体中文或英文
- **那么** 系统必须能识别对应语言的复制成功 toast 文案，且不得把「复制失败」类 toast 误判为成功；识别失败时不弹气泡且不影响其他入口

### 需求:气泡必须自动消失且不叠加
摘录气泡必须是轻量、可自动退场的提示，禁止常驻或重复叠加。

#### 场景:超时自动消失
- **当** 气泡弹出后 8 秒内用户未点击
- **那么** 气泡必须自动消失

#### 场景:重复触发不叠加
- **当** 气泡已显示时用户再次触发复制成功 toast
- **那么** 系统必须复用当前气泡并重置消失计时，禁止叠加新视图

### 需求:点击气泡必须拉起快摘弹窗
气泡是摘录弹窗在微信内的唯一触发入口，点击后必须以专用 action 拉起 `FastCaptureActivity`。

#### 场景:点击气泡
- **当** 用户点击摘录气泡
- **那么** 系统必须收起气泡并以 `ACTION_WECHAT_CAPTURE` 显式 Intent 拉起半屏快摘弹窗

### 需求:微信摘录气泡必须受独立开关控制
系统必须提供独立于无障碍服务的微信摘录气泡开关，默认开启，运行时即时生效。

#### 场景:关闭开关
- **当** 用户在设置页关闭「微信摘录气泡」开关
- **那么** 系统必须立即收起正在显示的气泡，且后续复制成功 toast 不再弹出气泡

#### 场景:重新开启开关
- **当** 用户重新打开开关
- **那么** 气泡能力必须恢复，无需重启无障碍服务

#### 场景:无障碍服务未开启
- **当** 用户未在系统设置开启辅助识别服务
- **那么** 气泡能力整体停用，开关仅作为偏好保留
