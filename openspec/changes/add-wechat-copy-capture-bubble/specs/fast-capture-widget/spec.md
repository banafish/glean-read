## 新增需求

### 需求:外部快摘必须支持微信摘录气泡入口
应用必须支持由无障碍摘录气泡以 `ACTION_WECHAT_CAPTURE` 显式 Intent 唤起快摘弹窗，并以两阶段方式填充种子数据。

#### 场景:气泡入口初始种子
- **当** `FastCaptureActivity` 以 `ACTION_WECHAT_CAPTURE` 启动
- **那么** 系统必须在 onCreate 阶段用最近页面上下文缓存补齐标题与 URL，正文保持为空
- **那么** 系统禁止把标题回退为正文

#### 场景:获焦后剪贴板填充
- **当** 气泡入口的弹窗首次获得窗口焦点
- **那么** 系统必须读取剪贴板并做新鲜度校验：普通文本填充为正文，`mp.weixin.qq.com` 链接填充为来源 URL 并回写页面上下文缓存

#### 场景:剪贴板不可用时降级
- **当** 剪贴板为空、内容陈旧或校验失败
- **那么** 弹窗必须保持缓存补齐的标题/URL 与空正文，用户可手动输入，保存不得被阻塞

#### 场景:分享入口不受影响
- **当** 弹窗以 `ACTION_SEND` 或 `ACTION_PROCESS_TEXT` 启动
- **那么** 系统禁止读取剪贴板

## 修改需求

### 需求:双场景 URL 感知
系统必须能够区分并处理「整页分享」「选中文字分享」「系统文本处理」与「微信摘录气泡」四类入口的来源信息差异，并在标准 `Intent`、剪贴板（仅气泡入口）与最近页面上下文缓存之间按优先级补齐 URL 和标题。

#### 场景:整页分享时的 URL 自动填充
- **当** 用户使用浏览器的「分享整页」功能分享到 GleanRead
- **那么** 弹窗必须优先从标准 `Intent` 字段中提取并填充来源 URL
- **那么** 若 `Intent` 已提供完整来源信息，系统禁止再用缓存覆盖它

#### 场景:选中文字入口的来源补齐
- **当** 用户通过分享或文本处理入口只传入选中文字正文
- **那么** 系统必须先尝试从 `Intent` 文本、附加字段或 `clipData` 提取 URL
- **那么** 若标准提取仍然不足，系统必须继续尝试使用最近页面上下文缓存补齐标题和 URL

#### 场景:气泡入口的来源补齐
- **当** 用户通过微信摘录气泡唤起弹窗
- **那么** 正文必须来自通过新鲜度校验的剪贴板文本，标题与 URL 优先来自最近页面上下文缓存
- **那么** 剪贴板内容为公众号链接时必须填充 URL 而非正文

#### 场景:来源完全缺失时降级
- **当** 标准 `Intent` 解析、剪贴板与最近页面上下文缓存都无法提供有效 URL
- **那么** 弹窗必须展示可编辑的链接输入路径
- **那么** 用户不填写 URL 时仍然必须能够完成快摘保存
